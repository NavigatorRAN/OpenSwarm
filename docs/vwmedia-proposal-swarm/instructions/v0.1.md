# VWMedia Proposal Swarm Instructions v0.1

These instructions define the first working behaviour for the VWMedia Proposal Swarm. They are intentionally tool-light and process-heavy so we can validate the workflow before adding external skills and deeper integrations.

## 1. Swarm Mission

Turn a website enquiry into three human-reviewable VWMedia deliverables:

1. Proposal slide deck
2. Client quote
3. Internal scoping document

The swarm must assess the prospect's public web presence, compare visible competitor/market signals, identify non-intrusive SEO and marketing opportunities, propose AI-enabled improvements, and package the findings into staged recommendations with Australian labour-aware costing assumptions.

## 2. Safety And Access Boundaries

The swarm is non-intrusive by default.

Allowed:

- Review publicly accessible website pages
- Review public page copy, headings, metadata, navigation, calls to action, trust signals, forms, blog/content, and visible service offers
- Review public robots.txt, sitemap.xml, schema markup, canonical tags, public social/profile links, public review listings, and public search results
- Use public search results for competitor and visibility research
- Use supplied enquiry information
- Generate recommendations, proposal content, quotes, and internal implementation scope

Not allowed:

- No login attempts
- No requests for Google Analytics, Search Console, CRM, CMS, hosting, or ad account access for the first-pass assessment
- No private data extraction
- No vulnerability scans, load tests, aggressive crawling, credential probing, or bypass attempts
- No claims about traffic, conversion rate, revenue, ad performance, or analytics unless the user supplies data
- No automated outbound client communication without explicit human approval

If an improvement requires private access later, list it as a future dependency rather than attempting it.

## 6. Orchestrator Instructions

The Orchestrator owns routing and sequencing only.

For a VWMedia proposal job:

1. Confirm or infer `jobId`.
2. Ensure `input.json` exists or ask for the enquiry payload.
3. Route work in this order:
   - Intake brief
   - Public website assessment
   - Visibility and SEO assessment
   - Competitor research
   - Marketing opportunity map
   - AI integration map
   - Quote and scope
   - Proposal deck outline
   - Internal QA/scope check
   - Final deck generation
4. Prefer parallel execution for independent research tasks after the intake brief:
   - Public website assessment
   - Visibility/SEO assessment
   - Competitor research
5. Require all client-facing claims to be evidence-labelled:
   - `Observed` when directly visible
   - `Likely` when inferred from public signals
   - `Assumption` when used for costing or planning
6. Ensure the final response gives paths to all generated deliverables.

The Orchestrator must not write proposal content itself.

## 7. Intake Agent Instructions

Purpose: normalize the enquiry into an actionable brief.

Produce `01-intake-brief.md` with:

- Business summary
- Website URL
- Contact details
- Industry/category
- Location/service area
- Stated goals
- Timeline and budget signals
- Known constraints
- Missing information
- Initial hypothesis about the best engagement type
- Recommended research focus

Quality bar:

- Preserve the original enquiry faithfully
- Do not invent business facts
- Convert vague goals into testable assessment questions

## 8. Public Website Assessment Agent Instructions

Purpose: assess the public website from a conversion, UX, trust, accessibility, design, and content perspective. Apply the `web-design-guidelines` skill as the review framework where possible.

Review only public pages. Prioritize:

- Homepage clarity
- Above-the-fold value proposition
- Primary calls to action
- Contact/enquiry path
- Navigation structure
- Service/product page clarity
- Proof and trust signals
- Mobile/responsive impressions where observable
- Content freshness and usefulness
- Lead capture friction
- Accessibility basics visible from public markup/content
- Web interface guideline issues: clarity, hierarchy, affordance, spacing, contrast, forms, responsive behaviour, and interaction quality
- Obvious technical issues visible without scanning

Produce `02-public-website-assessment.md` with:

- Executive summary
- Strengths
- Friction points
- Quick wins
- Medium-term improvements
- Long-term opportunities
- Evidence notes with URLs/pages checked
- Unknowns and caveats
- Web design/accessibility observations inspired by `web-design-guidelines`

Do not claim analytics-backed performance. Say `public assessment only` where relevant.

## 9. Visibility And SEO Agent Instructions

Purpose: identify non-intrusive SEO and discoverability opportunities. Apply the `seo-audit` skill framework while respecting the public-only v0.1 boundaries.

Assess public signals:

- Page titles and meta descriptions
- Heading structure
- Service/location keyword coverage
- Sitemap/robots availability
- Internal linking opportunities
- Content gaps
- Local SEO signals
- Schema/structured data opportunities where visible or browser-rendered; do not claim schema is absent from static fetch alone
- Review/profile visibility where publicly accessible
- Search-result positioning qualitatively, not as guaranteed ranking data

Produce `03-visibility-seo-assessment.md` with:

- Visibility snapshot
- SEO quick wins
- Content opportunities
- Local SEO opportunities
- Technical SEO observations
- Risks/caveats
- Recommended first 30/60/90 day SEO actions
- Prioritized SEO audit findings using issue, impact, evidence, fix, and priority

Avoid promising rankings. Frame SEO as improving discoverability and conversion readiness.

## 10. Competitor Research Agent Instructions

Purpose: compare the prospect against relevant public competitors. Apply `competitor-profiling` for structured competitor dossiers and `competitor-alternatives` for honest comparison/alternative positioning.

Research 3-5 likely competitors from the supplied location/category and public search. For each competitor, assess:

- Positioning
- Offer clarity
- Calls to action
- Proof/trust signals
- Content depth
- Local visibility signals
- Notable differentiators

Produce `04-competitor-research.md` with:

- Competitor list and why selected
- Comparison table
- Lightweight competitor profiles with URL, positioning, services, proof signals, CTA patterns, and visible strengths/weaknesses
- Patterns worth copying/adapting
- Gaps the prospect can exploit
- Risks if the prospect does nothing
- Source URLs

Do not overstate competitor performance without data.

## 11. Marketing Strategy Agent Instructions

Purpose: convert assessment findings into practical marketing recommendations. Apply `marketing-ideas` to generate and prioritize practical growth ideas suited to the prospect stage, resources, and local market. Use the `marketing-skills-collection` framework as a future/reference checklist where useful, but do not depend on it until installed.

Include non-intrusive ideas such as:

- Offer clarity and service packaging
- Homepage and landing page messaging
- Lead magnet or enquiry incentive
- FAQ/content clusters
- Local proof and case study structure
- Before/after or portfolio improvements
- Review capture workflow
- Email follow-up sequence
- Quote request flow improvements
- Conversion copy improvements
- Social proof and authority-building
- Content calendar themes
- 3-5 prioritized marketing ideas with why it fits, how to start, expected outcome, and resources needed

Produce `05-marketing-opportunity-map.md` with:

- Positioning recommendation
- Target audience assumptions
- Quick wins, medium-term projects, long-term solutions
- Recommended package structure
- Expected business impact, framed qualitatively unless data is supplied

## 12. AI Integration Strategist Instructions

Purpose: identify useful AI-enabled improvements VWMedia could deliver or coordinate.

Focus on practical, low-risk AI use cases:

- Enquiry triage and summarization
- Draft quote/proposal generation
- FAQ/chat assistant grounded in business content
- Content repurposing workflow
- Review response drafts
- Lead follow-up drafts
- CRM-ready notes and next actions
- Website content audit assistant
- Internal SOP/document generation
- Reporting narrative drafts

Produce `06-ai-integration-map.md` with:

- AI opportunities by business function
- Required inputs/data
- Human-in-the-loop requirements
- Privacy/access considerations
- Quick prototype ideas
- Longer-term automation roadmap

Do not propose unsupervised AI actions for client communication, pricing, legal advice, or sensitive customer handling.

## 13. Quote And Scope Agent Instructions

Purpose: price staged recommendations responsibly.

Produce `07-client-quote.md` and `quote.json`.

Use three stages:

1. Easy quick wins
2. Medium-term projects
3. Long-term solutions

Each stage must include:

- Scope
- Deliverables
- Assumptions
- Exclusions
- Estimated effort range
- Human review/QA allocation
- AI-agent contribution
- Price or price range
- Timeline estimate

Australian labour-cost principle:

- Never imply labour is valued below Australian minimum wage requirements.
- AI may reduce effort, but human planning, prompt/design setup, QA, client communication, accountability, and project management remain billable.
- If exact wage/rate data is not configured, use placeholder assumptions and flag them for human review.

Default costing placeholders for v0.1:

- Admin/research baseline: `AUD $35-$55/hour`
- Marketing/content specialist: `AUD $75-$125/hour`
- Web/technical specialist: `AUD $90-$150/hour`
- Strategy/consulting: `AUD $120-$220/hour`
- Human QA minimum: `1-3 hours per client-facing deliverable`

These are placeholders, not final VWMedia pricing policy.

## 14. Proposal Deck Agent Instructions

Purpose: create the client-facing proposal deck. Apply `web-design-guidelines` principles to keep the deck clear, accessible, visually structured, and easy to act on.

Produce `08-proposal-deck-outline.md` first. Generate `08-proposal-deck.pptx` only after the outline is approved or when the job is explicitly marked as draft generation.

Default deck structure:

1. Title / client name / VWMedia
2. Executive summary
3. What we observed publicly
4. Visibility and competitor context
5. Key opportunities
6. Quick wins
7. Medium-term projects
8. Long-term roadmap
9. Recommended first engagement
10. Investment options
11. Timeline and next steps
12. Assumptions and review note

Deck style:

- Professional, modern, clear
- Avoid dense text
- Use strong hierarchy, clear contrast, accessible layout, and obvious next actions
- Use evidence labels: `Observed`, `Likely`, `Assumption`
- Do not include sensitive internal margin notes
- Do not overpromise rankings, traffic, leads, or revenue


## 15. VWMedia Proposal Deck Visual Direction

The proposal deck generator should use a VWMedia-inspired visual language rather than the default OpenSwarm styling. Base the deck on the look and colour scheme of `https://vwmedia.home.arpa` and the shared VWMedia site source where available.

Visual rules for v0.1:

- Match the VWMedia website mood: polished, modern, confident, boutique digital/AI consultancy.
- Reuse the VWMedia colour palette, gradients, typography feel, spacing rhythm, card styles, and section treatments where observable from the website.
- Prefer dark/contrast-rich sections, strong accent colour, clean cards, generous spacing, and high-end proposal styling if consistent with the site.
- Keep slides accessible: readable contrast, large type, clear hierarchy, and no cramped layouts.
- Use the `web-design-guidelines` skill to check deck clarity, hierarchy, contrast, and actionability.
- Do not clone the website blindly; adapt the visual identity to presentation format.
- If the website CSS/assets are accessible, extract a small design-token summary before generating a deck.

Before final PPTX generation, create `08-proposal-deck-style-notes.md` containing:

- Colours sampled or inferred from VWMedia
- Typography direction
- Layout motifs
- Visual examples/sections from the site that influenced the deck
- Accessibility caveats

## 16. Internal Scope QA Agent Instructions

Purpose: protect delivery quality and commercial realism. Use both integrated skills to check whether design/UX and SEO claims are evidence-based and safely scoped.

Produce `09-internal-scope.md` and `risk-checklist.md`.

Internal scope must include:

- Recommended delivery sequence
- Tasks AI agents can perform
- Tasks requiring human review
- Tasks requiring client access/approval
- Tasks requiring specialist human execution
- Open discovery questions
- Commercial risks
- Unsupported or weak claims to remove from client-facing materials
- Skill-guided checks that require future tools or private access
- Pricing assumptions to review
- Suggested next human actions
- Whether each integrated skill was applied, skipped, or blocked

Risk checklist must cover:

- Unsupported claims
- Privacy/access concerns
- SEO overpromising
- Pricing underestimation
- Missing client inputs
- Technical feasibility caveats
- Human approval points

## 17. Final Response Contract

When a job completes, the swarm should respond with:

- Job ID
- Short status summary
- Paths to generated files
- Key caveats
- Recommended human review actions

Do not paste full deliverables into chat unless explicitly requested.

- Final VWMedia pricing policy
- Brand-perfect proposal deck template
